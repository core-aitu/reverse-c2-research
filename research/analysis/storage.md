# Модель хранения

В поставке согласуются три независимых признака PostgreSQL — образ postgres:16.4 в Compose, зависимость Npgsql в манифесте и SQL в IL серверной сборки. Для слоя документации сервер содержит сущность DocumentationChunk и код создания таблицы. FND-004, FND-011.

| Поле в объявлении DDL | Тип и ограничение |
|---|---|
| id | SERIAL PRIMARY KEY |
| Path, Title, Content | TEXT NOT NULL |
| Embedding | real[], допускает NULL |
| ChunkIndex | INTEGER NOT NULL, значение по умолчанию 0 |
| IndexedAt | TIMESTAMPTZ NOT NULL, значение по умолчанию NOW() |

Код содержит создание уникального индекса по паре Path и ChunkIndex. Имена в таблице выше воспроизводят написание в строке SQL. Для установления фактического регистра идентификаторов, состава индексов и применённых миграций нужен каталог действующей БД. Поиск отдельного снимка в этой поставке не дал кандидатов. Наличие 33 типов в пространстве имён сущностей также не устанавливает число таблиц. FND-011, FND-016.

Дерево административного ответа имеет отдельную модель. Name именует узел, Contents содержит Markdown, Children — коллекцию дочерних узлов. Отношение родитель–потомок подтверждено вложенным ответом. Материал исследования не устанавливает внешнего ключа между таким узлом и строкой поискового индекса. FND-007, FND-008.

## Расширенная проверка

На чистой PostgreSQL 16.4 штатная Server.dll фактически создала таблицы с именами documentationchunks и event. В системном каталоге оказалось соответственно семь и девять столбцов. Повторная запись того же ключа обновила данные. Для отдельной установки всё ещё нужны её собственная схема и история миграций. [Протокол проверки](../validation/postgres/run-1.jsonl)
