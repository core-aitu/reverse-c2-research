# Поисковые фрагменты и журнал аудита в PostgreSQL

18 ноября 2026 года два экземпляра PostgreSQL 16.4 на пустых кластерах независимо выполнили один опыт. В каждом штатная Server.dll дважды вызывала методы создания таблиц. После сценария записи и чтения стенд запросил системный каталог и проверил две повторные вставки непосредственно через SQL. В обоих прогонах совпали определения столбцов, ограничения, индексы и результаты вставок. Для сравнения со схемой действующей установки по-прежнему нужна её выгрузка. [Первый каталог и пробы](../validation/admin-storage/run-1.json) · [Независимый повтор](../validation/admin-storage/run-2.json)

## Идентичность строк

| Таблица | Первичный ключ | Что происходит при совпадении прикладных полей |
|---|---|---|
| `public.documentationchunks` | `id integer`, последовательность `documentationchunks_id_seq` | Отдельный уникальный индекс B-tree `ix_doc_chunks_path_idx` охватывает пару `(path, chunkindex)`. Две прямые вставки с одним путём и пропущенным номером фрагмента получили значение по умолчанию 0. Вторую PostgreSQL отклонила с кодом `23505` и именем этого индекса. |
| `public.event` | `id integer`, последовательность `event_id_seq` | Текстовое `identifier` обязательно. Копирование одной синтетической строки с прежним `identifier` дало две строки с разными `id`. Единственный индекс таблицы в каталоге этого стенда обслуживает первичный ключ. |

Уникальность фрагмента объясняет, почему для хранения нескольких частей одного документа требуется различать их номера. Штатный метод `UpsertDocumentationChunkAsync` в проверенном сценарии обновил содержимое существующего фрагмента и сохранил число строк. Прямой SQL опыт выше независимо выявил ограничение, которое действует при обычной вставке. Для аудита опыт подтверждает допустимость дубликата на уровне хранения. Для вывода о повторной доставке события клиенту требуется отдельное наблюдение приложения. [Код штатного сценария](../validation/postgres/Program.cs) · [Пробы и запрос к каталогу](../validation/admin-storage/schema.sql)

## Столбцы и ограничения

| Таблица | Обязательные поля | Допускает NULL | Значения по умолчанию |
|---|---|---|---|
| `documentationchunks` | `id`, `path`, `title`, `content`, `chunkindex`, `indexedat` | `embedding real[]` | `id` из последовательности, `chunkindex = 0`, `indexedat = now()` |
| `event` | `id`, `identifier`, `timestamp`, `type`, `source`, `outcome`, `system`, `message`, `details` | — | `id` из последовательности |

На стенде `indexedat` и `timestamp` имеют тип `timestamp with time zone`. У `event` семь текстовых столбцов, включая `details` и `outcome`. Запрос к `pg_constraint` вернул по одному первичному ключу на таблицу. Уникальность пары в `documentationchunks` отражена непосредственно в `pg_index`. Если переписывать схему по одному только списку ограничений, этот индекс будет упущен. Обязательность полей считана из `pg_attribute.attnotnull`. Внешних ключей на стороне этих двух таблиц в проверенной схеме не обнаружено. [Снимок каталога](../validation/admin-storage/run-1.json)

## Повторение

SDK и PostgreSQL для обоих запусков извлечены из локального архива среды. Код стенда заново собран. Каждый запуск создал новый кластер в отдельном пространстве имён и использовал Unix-сокет. Оба набора из 19 записей штатного сценария побайтно совпали с сохранённым контролем. Оба JSON с каталогом и SQL-пробами имеют SHA-256 `7b5a190bfe4286c65bf1e270703c6ca826b7b3e95d2725fba73b1ce5c8f47ca5`. Время и хеши входных файлов указаны в протоколе. [Протокол](../validation/admin-storage/runs.json) · [Контрольный журнал](../validation/postgres/run-control.jsonl)

Из корня исследовательского репозитория выполнить команду с путями к извлечённым SDK и PostgreSQL и к локальной исходной поставке. Каталог сборки должен быть доступен для записи.

```sh
research/validation/admin-storage/repeat.sh "$sdk" "$dist" "$pg" "$build" > catalog.json
cmp catalog.json research/validation/admin-storage/run-1.json
```

Запрос охватывает две таблицы, созданные явными вызовами серверных методов в стенде. История миграций, схема уже развёрнутой базы и автоматический вызов этих методов при штатном старте остаются открытыми. [Модель хранения](../analysis/storage.md)
