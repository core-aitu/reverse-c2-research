# Откуда панели Kibana получают данные

**Проверено статически по локальному экспорту.** Все 35 размещений на шести дашбордах ссылаются на 35 разных объектов. Для каждого установлено представление данных (data view), указанное в сохранённом поиске, визуализации или слое карты. Шесть размещений дополнительно содержат собственную копию визуализации. В двух таких копиях на дашборде Infrastructure указан другой идентификатор представления. Это существенно при проверке того, как выбор времени влияет на отображение. [Граф с идентификаторами размещений, объектов и источников](../examination/observability/data-views.json)

## Представления и потребители

В экспорте есть два объекта типа `index-pattern` с одним шаблоном имени индекса `specter*`. У представления `b7f2f870-b395-4a89-8d17-570aa428aa53` поле времени — `@timestamp`. У `709afdbd-b63b-409f-823a-b6982e063d3f` значение `timeFieldName` пустое. Оба объекта содержат пустые списки `fields` и пустые `runtimeFieldMap`. Фактическая схема и документы Elasticsearch в этих записях отсутствуют. [Свойства представлений](../examination/observability/data-views.json)

| Тип сохранённого объекта | Представление с полем времени | Представление с пустым полем времени |
|---|---:|---:|
| Визуализация | 25 | 3 |
| Сохранённый поиск | 3 | 2 |
| Карта | 0 | 2 |
| Всего | 28 | 7 |

Для визуализаций и поисков проверена именованная ссылка из основного `searchSourceJSON.indexRefName`. Для карт проверялись ссылки каждого слоя по `sourceDescriptor.indexPatternRefName`. В каждой карте дополнительно объявлен базовый слой `EMS_TMS` без ссылки на одно из этих представлений. В таблице карта учитывается один раз, даже если к тому же представлению обращаются два её слоя. Фильтры и элементы управления дашбордом в счётчик основных источников не входят. [Метод проверки](../examination/observability/read_views.py)

## Два определения источника на одном дашборде

Для каждого размещения имя ссылки собирается из `panelIndex` и `panelRefName`, затем проверяются тип и идентификатор объекта назначения. Если в `embeddableConfig.savedVis` имеется вложенная визуализация, её `data.searchSource.indexRefName` разрешается в пространстве имён этого размещения. Из шести вложенных определений четыре указывают на то же представление, что и связанный объект. Для двух размещений дашборда Infrastructure (`454f42ea-e123-487a-9ac2-08bc5958b8e2` и `286bed6e-d539-41da-a828-c400ddf0eb69`) связанный объект ссылается на представление с `@timestamp`, а вложенное определение указывает на представление с пустым полем времени. Эффект при применении временного фильтра и выбор источника конкретной версией Kibana остаются открытыми. [Размещения и встроенные источники](../examination/observability/data-views.json)

## Воспроизводимость

Входом служит файл `elastic/elastic/dashboards.ndjson` из исходной поставки, SHA-256 `4ec038f77fc1e617e966d8f2af4be64dccbcca886126ea88247544a32ed05841`. Из корня исследовательского репозитория можно сравнить сохранённый граф с результатом повторного чтения.

```sh
python3 research/examination/observability/read_views.py ../SpecterInsight/elastic/elastic/dashboards.ndjson |
  diff - research/examination/observability/data-views.json
```

Проверка описывает конфигурацию экспорта. Для проверки отображения нужны импорт в совместимую версию Kibana, тестовый индекс с известными типами полей и наблюдение запросов при переключении диапазона времени. Наличие данных в рабочей установке и доступность картографической подложки остаются непроверенными. [Исходная проверка целостности экспорта](distribution-integrity.json)
