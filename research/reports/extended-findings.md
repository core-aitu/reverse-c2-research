# Расширенная проверка сборок, Beacon, хранилища и клиента

## Покрытие IL

System.Reflection.Metadata прочитал 1 777 PE/CLI, соответствующих 1 330 различным SHA-256. По уникальным образам обследованы 1 775 285 определений методов. У 1 650 441 тела IL проверены декодирование операций и операндов, границы переходов и границы областей исключений. У 124 778 определений отсутствует RVA, ещё у 66 указан другой вид кода. В этой проверке ошибок структуры не обнаружено. Верификация стека типов и эквивалентность поведения в задачи этого декодера не входят. [Результаты по каждому образу](../analysis/il-structure.jsonl)

Для 32 выбранных образов отдельный декодер на dnfile/dncil воспроизвёл число тел, инструкций, байтов IL и методов с обработчиками исключений по каждому SHA-256. Оба подсчёта дали 41 115 тел, 1 171 582 инструкции и 3 276 280 байт IL. У оставшихся 3 781 определений из 44 896 отсутствует RVA. [Независимый подсчёт](../validation/independent-il.json)

Для 13 514 методов исследованной выборки установлена узкая семантика. Каждый связан со свойством через метаданные, а всё его тело совпадает с чтением либо записью собственного поля соответствующей статичности. Классификатор не присваивает предметное назначение этим полям. Индивидуальный разбор 56 методов и автоматическая классификация аксессоров могут пересекаться. ## Beacon и соответствие исходникам

Для серверного SpecterInsight.exe отладочные записи PE указали на portable PDB с совпадающими GUID и stamp. После обнуления поля идентификатора PDB совпала и отдельная контрольная сумма SHA-256, записанная в PE. Для каждого из **65 документов** этого PDB в дереве templates/source нашёлся файл с совпадающими именем и контрольной суммой содержимого. Тот же результат применим к побайтно идентичному templates/any/specter-dotnet-exe.exe. Это устанавливает связь между локальными файлами исходного текста, символами и этим образом. Воспроизведение сборки из исходников и выполнение Beacon в опыт не входили. [Связи PE и PDB](../evidence/debug-bindings.json)

Среди шести путей к управляемым EXE в сравнении обнаружено пять разных SHA-256. Для четырёх остальных образов подходящий portable PDB не найден среди 362 распознанных portable PDB поставки. Для всех десяти пар опубликовано пересечение мультимножеств хешей байтов IL. Совпадение последовательности байтов может встречаться у разных методов, а смысл одинакового токена зависит от метаданных образа. Эта метрика служит для сравнения образцов. Она не даёт процент функциональной эквивалентности. Двенадцать нативных шаблонов x86/x64 представлены восемью разными файлами. Проверены архитектура PE, признак DLL и сравнимость групп секций. [Сравнение вариантов](../evidence/variant-comparison.json)

## PostgreSQL и события

В одноразовом кластере PostgreSQL 16.4 исследовательский стенд создал штатный DatabaseService с NpgsqlDataSource. Через методы поставляемой Server.dll дважды запрошено создание таблиц. Каталог PostgreSQL подтвердил две таблицы — documentationchunks с семью столбцами и event с девятью. Повторная запись документа с теми же Path и ChunkIndex обновила содержимое и embedding, сохранив число строк. Изменение ChunkIndex создало вторую строку. Штатные методы чтения и очистки вернули ожидаемые результаты. Каждому прогону выделялась новая БД с Unix-сокетом в изолированном пространстве имён. [Стенд](../validation/postgres/Program.cs) · [Журнал PostgreSQL](../validation/postgres/run-1.jsonl)

Служба EventLoggingService получила два синтетических события. Настоящий DatabaseService записал оба, тестовая реализация интерфейса SignalR увидела оба идентификатора. На втором вызове тестовая реализация вернула ошибку отправки. При этом вызов службы завершился и сохранённое событие удалось прочитать штатными фильтрами по типу и времени. После удаления одного типа в БД осталась только первая запись. Условия проверены в двух независимых кластерах. Открытым остаётся доставка по сетевому SignalR-соединению реальной установки. [Второй прогон](../validation/postgres/run-2.jsonl) · [Путь события](../interactions/audit-event.md)

## Что видит клиент

Сериализованная серверная запись из предыдущего опыта подана в модель Event сборки ApiClient. Идентификатор fixture-2 и исход Failure сохранились. На этом объекте штатный UI-конвертер выбрал красный цвет. Штатный метод EventLogViewModel.IsMatch пропустил записи с подходящими сообщением, источником или подробностями и исключил записи с другим типом, без совпадения текста или за пределами временного окна. Для проверки времени стенд изменял только timestamp относительно текущей границы ViewModel. Отдельные проверки охватили цвета событий, булевы привязки и обратное преобразование шести UI-конвертеров. Сериализацию между стендами выполнял исследовательский код. Окно приложения не открывалось. [Входная запись](../validation/postgres/run-1.jsonl) · [Результаты клиента](../validation/presentation-and-data/run-1.jsonl)

## Расхождение в справочнике производителей

Штатному серверному загрузчику передан поставляемый mac-vendors-export.csv. Независимый CSV-парсер насчитал 39 527 уникальных шестизначных префиксов. Для 22 829 строк имя производителя совпало полностью. Для 16 663 различалось. Ещё 35 префиксов отсутствовали в результате продукта, у всех 35 в CSV пустое поле производителя. Для 16 662 из 16 663 различий результат равен части имени до первой запятой. Оставшееся различие в эту группу не попало. 17 927 строк с префиксами другой длины исключены из этих сравнительных чисел. [Измерения на файле поставки](../validation/presentation-and-data/run-1.jsonl)

Контрольный пример подтвердил причину распространённого расхождения. Для CSV-поля в кавычках со значением «Example, Incorporated» сервер вернул «Example». При дубликате префикса сохранилось первое простое имя. Эти результаты относятся к импорту справочника и показу производителя. [Код и входные значения](../validation/presentation-and-data/Program.cs) · [Повтор](../validation/presentation-and-data/run-2.jsonl)

## Локальная модель поиска и ресурсы

В автономном стенде штатная SmartComponents.LocalEmbeddings открыла поставляемые model.onnx и vocab.txt. Нативная библиотека ONNX Runtime из каталога Linux x64 выполнила расчёт на двух синтетических текстах. Получены массивы по 384 конечных числовых значения. Повтор текста дал покомпонентно равные значения float в этих примерах. В функции CosineSimilarity из Server.dll сходство одинаковых векторов оказалось близко к единице, у разных текстов оно было ниже. Для двух ортогональных контрольных векторов функция вернула значение, близкое к нулю. Стенд проверяет совместимость модели, токенизации и функции сравнения. Качество поиска по большому корпусу не оценивалось. [Измерения](../validation/local-search/run-1.jsonl) · [Код опыта](../validation/local-search/Program.cs)

Функция ChunkByHeadings из той же серверной сборки сохранила Markdown-заголовки в тексте соответствующих фрагментов. Для текста без заголовка использовалось переданное название по умолчанию. Для пустой строки результат содержал один именованный фрагмент с пустым текстом. Все десять условий поиска и разбиения повторились в трёх изолированных прогонах. [Контрольный прогон](../validation/local-search/run-control.jsonl)

Для GeoLite2-City.mmdb прочитаны метаданные формата MaxMind DB 2.0. В файле указаны восемь языков, 3 973 755 узлов и дата сборки 19 июля 2024 года. Для зарезервированного тестового адреса 192.0.2.1 запись не найдена. Дата здесь относится к ресурсу GeoIP и самостоятельного основания для датирования приложения не даёт. [Протокол чтения](../examination/geoip-metadata.txt)

## Связность поставки

В манифестах UI, Host и автономной Server сверены 830 объявлений зависимостей пакетов. В каждом соответствующем графе нашёлся узел с требуемым именем и версией. Для ресурсов с локализацией учитывалась пара «каталог языка и имя DLL». У UI и Host каждому из соответственно 362 и 360 объявлений файлов сопоставлен путь по принятому правилу. У автономной Server из 236 объявлений восемь не нашли совпадения по имени, ещё 19 имели неоднозначное совпадение по имени в подпапках. Это результат проверки физической раскладки. Поведение загрузчика в каждой целевой ОС отдельно не установлено. [Сверка пакетов и файлов](../architecture/distribution-integrity.json)

В экспорте Kibana все 101 ссылки разрешились внутри 43 сохранённых объектов. У всех 35 размещений панелей в шести dashboard совпали ссылка, существование цели и тип объекта. Импорт этого экспорта в действующую Kibana не проводился. [Сверка объектов](../architecture/distribution-integrity.json)
