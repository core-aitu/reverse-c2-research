# Индивидуальный разбор обновления документации в UI

18 ноября 2026 года выполнено новое статическое чтение UI.dll средствами REA. Исходный SHA-256 и MVID совпали с предыдущим корпусом. Для четырёх методов совпали SHA-256 тел IL из двух выборок. Дополнительно проверено совпадение хешей с диапазонами байтов текущего бинарного файла. Программа продукта не запускалась.

## Первый статический проход

[Машинные карточки](../analysis/semantic-cards/documentation-ui.json) связывают каждый метод с сигнатурой, входами, результатом, изменениями состояния, собственными обработчиками ошибок, вызовами и координатами IL. Три карточки завершены в границах тела метода. Внутреннее поведение вызываемых библиотек отмечено отдельно. Карточка MoveNext остаётся частичной. Машинная проверка подтверждает структуру карточек и связь с байтами, смысловая интерпретация выполнена исследователем.

| Метод | Токен | Статус и результат |
|---|---|---|
| DocumentationViewer.OnAttachedToVisualTree | 0x06000158 | Разобрано локальное тело. Сначала вызывается базовый обработчик, затем get_ViewModel и UpdateDocumentation. |
| DocumentationViewer.OnDetachedFromVisualTree | 0x06000159 | Разобрано локальное тело. Есть только вызов базового обработчика и возврат. Собственной отмены задачи или очистки данных в override нет. |
| DocumentationViewModel.UpdateDocumentation | 0x06000917 | Разобрано локальное тело. Создаёт делегат Func<Task>, вызывает Task.Run на IL+12 и отбрасывает возвращённую задачу на IL+17. |
| Автомат UpdateDocumentation.MoveNext | 0x06000919 | Частично. Проверены ветки клиента, ожидание HTTP, постановка работы UI и две EH-области. Тело делегата UI 0x0600091c остаётся открытым. |

Три первые записи добавляют три новые индивидуально оформленные идентичности к прежним 121. MoveNext уже входил в прежние записи, повторно в сумму он не добавлен. Итог первого прохода — **124 индивидуальные записи IL**, из них **3 завершённые семантические карточки в границах локального тела**. Ещё одна карточка частичная. Это раздельные показатели; методы, затронутые только структурным индексом, в эти суммы не включены.

## Проверенные ветки автомата

- На IL+43 читается Globals.Client. При null переход на IL+52 ведёт к нормальному завершению без вызова DocumentationAsync. Сценарий с null динамически не проверялся.
- При наличии клиента DocumentationAsync вызывается на IL+58. Незавершённое ожидание сохраняет awaiter и state=0. Возобновление очищает сохранённый awaiter и устанавливает state=-1.
- После получения результата вызывается ToArray. Массив сохраняется в замыкании, которое передаётся диспетчеру UI.
- На IL+191 вызывается Dispatcher.InvokeAsync, а на IL+196 результат отбрасывается. В этом теле нет ожидания завершения делегата UI. Вывод о точном моменте появления текста требует наблюдения диспетчера и окна.
- Внутренняя область try [17,206) перехватывает System.Exception и вызывает NotifyAll на IL+206. Если уведомление завершилось нормально, автомат идёт к SetResult.
- Внешняя область try [14,215) включает вызов NotifyAll. Исключение в ней приводит к SetException на IL+233. Ошибка самого уведомления поэтому отличается от обработанной ошибки запроса.

Сохранённый графический опыт ранее показал, что после 503 уже загруженная страница остаётся видимой. Новый IL-разбор объясняет путь уведомления об ошибке, но не доказывает исполнение каждой ветви в том опыте. Поведение уведомления и ошибки делегата UI отдельно не инструментировались.

## Что нельзя заключить

Отсутствие отмены в одном override не устанавливает её отсутствие во всей программе. Отбрасывание Task не доказывает, что все ошибки остаются без уведомления. Внутренний обработчик автомата явно вызывает NotifyAll. Отсутствие проверки параллелизма в UpdateDocumentation само по себе не доказывает наблюдаемую гонку запросов. В первом проходе эти два сценария оставались открытыми. Результаты двух последующих прогонов приведены ниже.

## Порядок ответов, отмена и присваивание Documents

В UI.dll свойство `Documents` имеет тип `System.Object`. Делегат `0x0600091c` читает ссылки на модель и полученный массив на IL+1 и IL+7. На IL+12 он вызывает сеттер. Сеттер `0x06000915` передаёт адрес поля, новое значение и имя свойства `Documents` в `RaiseAndSetIfChanged` на IL+13. Геттер `0x06000914` возвращает значение того же поля. В проверенной цепочке каждый успешный ответ ставит в очередь присваивание целого массива. Проверки порядкового номера запроса здесь нет. Завершены семь карточек локальных тел, включая ранее частично описанный MoveNext. [Карточки](../analysis/semantic-cards/documentation-ui.json) · [Вызов сеттера и чтение полей](../examination/documentation-ui/callback-edges.json) · [Независимое чтение PE](../examination/documentation-ui/callback-body-check.json)

| Условие опыта в Xvfb | Наблюдение |
|---|---|
| Два запроса из одной модели. Второй получил ответ первым | Сначала окно и модель показали «Second request». После возврата первого запроса оба показали «First request». Надпись «Second request» исчезла. |
| Отмена активного HTTP-запроса через `HttpClient.CancelPendingRequests()` при открытом экране | Токен обработчика перешёл в состояние отмены. Задача исходного рабочего делегата завершилась со статусом `RanToCompletion`. В модели и в окне остался ранее загруженный документ. В этом опыте проверялось завершение задачи, без перехвата самого NotifyAll. |
| Экран отсоединён до возврата ответа | Токен обработчика оставался активным. После ответа модель получила «Detached response». На снятом экране надпись не появилась. |

Использовались поставленные UI и ApiClient. Ответы синхронизированы через управляемый тестовый HTTP-обработчик. При отмене стенд вызвал непосредственно исходный рабочий делегат, чтобы дождаться его завершения: публичный `UpdateDocumentation()` возвращает void и токена отмены не принимает. Принудительную отмену инициировал стенд. Два запуска дали побайтно одинаковые четыре строки. Для повторения передайте `documentation-cancel` пятым аргументом в скрипт экрана.
